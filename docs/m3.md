# Scheduling with the reference agents

Start the WSS hub and agents as in the M2 instructions. Send this command on agent A's stdin:

```json
{"command":"schedule","meetingId":"nov10","participantAgentIds":["agent-a","agent-b","agent-c"],"window":{"start":"2026-11-10T10:00:00+03:00","end":"2026-11-10T16:00:00+03:00"},"durationMinutes":60}
```

Query any agent with `{"command":"meeting","meetingId":"nov10"}`. The initiating agent reports the ranked slots and the members whose calendar writes are outstanding. The default fixture is `packages/protocol/fixtures/calendar-v1.json`. Each agent seeds its own persistent calendar once. Supply a local profile with `--calendar-file` for a different dataset and use a fresh state directory for a clean run.

| Transition | Durable state |
| --- | --- |
| REQUEST and availability proposals | Coordinator waits for every participant's scored slots, including its own. |
| Selection and local vote | A participant checks and holds the slot before ACCEPT. A negative vote or the coordinator's predecision deadline records ABORT. |
| Unanimous ACCEPT | The coordinator persists one decision ID before sending COMMIT or writing its calendar. |
| Accepted participant loses contact | The hold survives the deadline. PENDING_RECOVERY requests the decision using a fresh signed SYNC message. |
| Calendar write | Each agent reconciles a stable local event key before reporting APPLIED. COMMIT_PENDING lists missing acknowledgments. |
| All APPLIED | The coordinator shows CONFIRMED. |

The agent's own SQLite file scopes event keys by agent, and its meeting table stores the round, version, votes, decision and recovery state. Replayed decisions refer to the original decision ID. Provider failures leave the operation pending. A round ID and decision version are part of the signed envelope. Scheduling uses half-open intervals and a 30-minute grid anchored to the requested start. The demo deadline defaults to 120 seconds. Existing event titles and descriptions stay in local fixture storage.

Run `npm run certs` and `npm run secrets` first. Set `DATABASE_URL` and `M3_TEST_DATABASE_URL` to a **disposable** PostgreSQL database. The regression and demo reset the hub tables for each scenario. Run `npm run demo:m3` for 20 clean normal runs and six failure/recovery scenarios. Run `npm run test:gate:m3` to include M1/M2 regressions and scheduling unit tests. JSON traces are written to `.state/evidence/m3/runs.json`. The fixture clock represents November 10 in Istanbul. Delivery deadlines use the actual process clock.
