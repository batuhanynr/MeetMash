# Air lab

MM-401 and MM-402 need an assigned NVIDIA simulation with reachable management hosts. The included local benchmark runs on Linux containers in Docker Desktop. The simulated deployment has not been verified on Air.

1. Import `topology.dot` with OOB management enabled and place swp1 through swp4 on the same access VLAN. Check that your quota covers one switch and four VMs and that the image IDs in the DOT are available. [NVIDIA topology import](https://docs.nvidia.com/dsx-air/custom-topology/) · [Management interfaces](https://docs.nvidia.com/dsx-air/oob-management-network/)
2. Install Docker on the four Ubuntu VMs. From the repository root, build a Linux image for the VM architecture using `docker buildx build --platform linux/amd64 --load -f infra/network/Dockerfile -t meetmesh-m4:air .` on the operator workstation. Transfer the output of `docker save meetmesh-m4:air` over each node’s OOB SSH connection into `docker load`. Record the repository SHA and image ID.
3. Copy `prepare-node.sh` to each dedicated VM. Run `sudo sh prepare-node.sh ROLE meetmesh-m4:air` once, with ROLE equal to the node name in the topology. This configures eth1 for data and starts a Linux container with a node-local state volume. SSH uses eth0. The data subnet is 10.76.4.0/24. Before use confirm the management subnet is different.
4. Generate the test CA and credentials with `npm run certs` and `npm run secrets`. Give the hub only its TLS certificate and key; give each agent only the public CA, its own bootstrap credential and its own pair keys. See the automated provisioning in `scripts/m4/lab.mjs`. Keep the CA signing key on the operator workstation.
5. On the hub VM start a disposable PostgreSQL 16 database on 127.0.0.1 and supply its DATABASE_URL to the hub container. The `provision` action of `infra/network/driver.mjs` loads the schema and hashes the test bootstrap credentials. Start the WSS hub with `--host hub-data --cert-dir /state/certs`; start each agent with its own `--id`, `--hub wss://hub-data:8787`, `--state-root /state/agents`, `--cert-dir /state/certs` and `--secrets /state/secrets.json`.
6. From each app node run `docker exec meetmesh-node sh infra/network/profile.sh PEER show` (`PEER=hub-data` on agents, `PEER=agent-a` on the hub). The data route must use eth1. Use the same script with `N1` or `N2` to apply the profile, `show` to capture settings/counters, and `reset` to remove it. The checked Docker fallback uses a `noqueue` root. On Air, record the VM’s original qdisc first; if it differs, the script refuses to overwrite it.
7. Capture the four app version/health records, a data-only outage with management commands still responding, a three-agent confirmed meeting, and the exported topology from the running simulation. Until those steps pass the Air deployment remains open.
